This page walks you through nod's onboarding, your first tasks and what to do when nod needs you.

## Onboarding at a glance

nod opens onboarding the first time you use it. In the desktop app, you can connect accounts while nod prepares its computer. Connect Gmail or skip it, choose an AI provider, then optionally connect other tools and Telegram or WhatsApp. nod gets to know you in the chat after setup.

```mermaid
flowchart TD
  start[Get started] --> hi[Say hi and<br/>usage data]
  hi --> gmail[Gmail or skip]:::muted
  gmail --> model[Connect<br/>a model]:::accent
  model --> apps[Other tools]:::muted
  apps --> messaging[Telegram or WhatsApp]:::muted
  messaging --> chat([Get to know nod<br/>in chat]):::go
```

## Go through onboarding

<Steps>

1. **Get started.** Select **Get started** on the welcome screen.

2. **Say hi.** nod introduces itself and asks whether to **Share usage data**. It's off unless you turn it on, and you can change it later in **Settings → General**. Select **Let’s go**.

3. **Connect email (optional).** Choose **Gmail** or **Outlook** to get help with replies and follow-ups. Sign in and review the permissions, or select **Skip for now**. Setup continues after the connection is confirmed. Failed sign-in does not erase your earlier progress.

4. **Connect a model.** Pick a provider. Each one shows how it connects: **ChatGPT plan** means you sign in with your ChatGPT Plus or Pro plan, and **API key** means you paste a key from the provider. For OpenAI, select **Sign in with ChatGPT** or paste an OpenAI API key. Anthropic takes an API key only, because Claude plans can't be used. For OpenRouter, select **Sign in to OpenRouter** to have it create a key for nod, or paste one. In the desktop app or a source install, you can instead pick **OpenAI-compatible** to use a [local model](/connect/local-models/): check the server address, add a key only if the server needs one, then select **Connect**. Your key is encrypted and never shown to the model. nod uses your provider’s default model when available. You can change it later in **Models**. Setup moves on once the new connection and model are ready; if a model choice is still needed, select one and then **Continue**.

5. **Connect other apps (optional).** Browse the categories or search by name, then select **Connect** and review the access requested by each app. Connected apps keep their place in the list. **Manage** opens the same account manager as Apps, where you can add another account or disconnect one. A count beside **Continue** shows connected tools, excluding email. Each app counts once, even with multiple accounts. Select **Continue** whenever you’re ready, including with no apps connected. You can add apps anytime from **Apps**.

6. **Take nod with you (optional).** Connect **Telegram** or **WhatsApp** to send tasks from your phone and continue the same conversation. Keep nod running on your computer so it can reply. Telegram walks you through creating a bot and confirming your account; WhatsApp links your own number with a QR code; use **Message yourself** to talk to nod. You can connect either, both, or **Skip for now**.

7. **Open at login.** In the desktop app, enable **Open at login**, then select **Start chatting**. The first chat requests desktop notifications once. You can change both preferences in **Settings → General**.

</Steps>

Setup finishes after the messaging choice in the web app, or after desktop preferences in the app. If the computer is still preparing, nod shows its progress and opens chat automatically when ready. If it is already ready, chat opens directly.

You can add more later from **Apps** and **Channels** in the sidebar. See [Connect apps](/connect/apps/) and [Channels](/use/channels/).

To revisit setup in your browser, open `/onboarding?replay=1` on your nod address. This returns to Welcome while keeping saved connections and settings.

In the desktop app, **Replay onboarding** opens setup again without deleting saved connections or preferences. While first setup is still running, it returns to your current step. For a separate empty test install on a Mac, use the [Mac test installer](/contribute/desktop-releases/#test-a-local-mac-build); it creates a new isolated profile.

## Start your first task

nod opens the conversation by asking what you're working on and what it can take off your plate. Reply in chat, or ask for a task directly. There is no required interview. What you share follows the normal chat memory settings.

On a new desktop installation, nod requests notification permission when its first chat message appears, so it can tell you when work is ready or needs your attention. Your operating system may show a permission prompt. If you decline, nod does not ask again automatically; you can allow notifications in your system settings later. Existing notification choices are kept. Desktop alerts do not authorize app monitoring or scheduled work.

nod also prepares three starting task cards: one **Right now** and two **Ongoing** ideas. If you connected Gmail, it can use a short inbox summary or recent subjects and snippets to make those suggestions useful. Existing saved setup answers can still inform them. You can ignore the cards and type any request.

Each card shows where the task comes from (**Gmail**, **For you** or **Telegram**). Select **Do it**, or **Set it up** on an ongoing card, to send the card's title to nod as your message. The card shows **On it…** while nod works, then **Done** or **Set up**. You can also ignore the cards and type any request.

:::note[A card isn't your permission]
The card's words are nod's, not yours. They can't on their own approve sending something to other people or deleting data, now or in a schedule the card set up.
:::

## Write a good first request

- **Say what done looks like:** "Compare these three suppliers and put the price and delivery time in a table."
- **Name the account or site:** "Download last month's invoice from billing.example.com with my saved login."
- **Say whether to send or draft:** "Draft a reply to the Northstar quote. Don't send it."
- **Ask for a schedule in plain words:** "Every Monday at 9 am, send me a summary of new client email."

You can keep writing while nod works. nod reads new messages before its next step.

## When nod needs you

| nod needs                    | What you see                                                       | What you do                        |
| ---------------------------- | ------------------------------------------------------------------ | ---------------------------------- |
| A choice or a missing detail | A question in the chat                                             | Reply in the chat                  |
| Your OK for an action        | "Reply yes to go ahead, no to skip it, or tell me what to change." | Reply **yes** or **no**            |
| A password, code or card     | A private form, such as **Sign in** or **Approve payment**         | Enter it in the form, not the chat |
| You to use a website         | An **Open browser** link                                           | Take over, then select **Done**    |

What you type in a private form goes to the website, not to the model. nod never asks for a password, code, card number or API key in the chat. See [Approvals and the trust check](/trust/approvals/) and [Vault](/trust/vault/).

## Stop nod

To stop nod, select **Stop**, the square button next to the send button. It shows while nod is working. nod stops the current work and cancels anything still queued. Stopping can't undo an action that already started, such as an email that's already on its way.
